# GenCompass

Рабочий веб-прототип Lumen Genomics по `GenCompass_PRD_Design.md` от 04.09.2026, с правками пользователя из браузера.

Реализованы данные пациента и приёма; восемь открытых групп клинических признаков; закреплённая полоса этапов; мгновенный демо-индекс; объяснение вкладов и источники; сохранение черновиков и результатов в D1; история и повторное редактирование; направление, TXT и печать / сохранение PDF через диалог браузера. Русский интерфейс адаптирован к десктопу, планшету и телефону.

## Дизайн-система

Интерфейс построен на [Astryx 0.5.2](https://astryx.atmeta.com/docs/getting-started): `@astryxdesign/core` и готовая тема `@astryxdesign/theme-neutral`. Токены Neutral задают цвета, типографику, интервалы и скругления. Светлый режим включён по умолчанию; переключатель в навигации включает тёмный режим той же темы.

Каркас, формы, календарь, выбор признаков, таблицы, шаги, диалоги и уведомления используют компоненты Astryx. Семантические цвета результата сохранены. Русский каталог подключён через `InternationalizationProvider`; даты вводятся в формате `дд.мм.гггг`. На телефоне навигация открывается меню, шаги показывают короткие подписи, а таблицы прокручиваются внутри своей области.

Правила библиотеки доступны в `AGENTS.md` и через `npm run astryx -- docs <topic>`. Используется готовая тема без ручного переопределения токенов. Остаточные компоненты стартера в `components/ui` не используются текущими экранами.

## Запуск приложения

Требуется Node.js 22.13+.

```sh
npm ci
npm run db:migrate:local
npm run dev
```

Локальный адрес выводится сервером (обычно http://localhost:3000).

```sh
npm run test
npm run typecheck
npm run lint:app
npm run build
```

`npm run lint` также проверяет поставляемый каталог компонентов стартера и сообщает его исходные замечания. `lint:app` проверяет авторский код приложения. Компоненты стартера не редактировались для подавления этих замечаний.

## GitHub Pages

Статическая версия использует тот же интерфейс Astryx Neutral и Dev tools с автозаполнением. Она публикуется из `main` workflow-файлом `.github/workflows/pages.yml`; работа в отдельной ветке не обновляет опубликованную версию.

```sh
npm run build:pages
npm run preview:pages
```

Готовые файлы находятся в `dist-pages/`; базовый путь по умолчанию — `/gencompass/`. Для другого имени репозитория задайте `PAGES_BASE_PATH` при сборке. Workflow делает это автоматически. В настройках GitHub Pages выберите источник **GitHub Actions**.

На Pages нет серверной базы и входа в аккаунт. Сохранённые оценки записываются в `localStorage` только этого браузера; временный ввод и резервная форма Dev tools — в `sessionStorage`. Данные не отправляются в GitHub и не синхронизируются между устройствами. Очистка данных сайта удаляет локальную историю. Это публичный демонстрационный интерфейс: используйте вымышленные данные. Локальная D1-база и сохранённые оценки не входят в репозиторий или артефакт публикации.

Сборка Sites/D1 продолжает использовать `npm run build`; статическая версия не меняет её API и базу. `lib/persistence.ts` выбирает нужное хранилище при сборке.

## Модель и данные

- `lib/clinical-data.json`: клинические признаки, демовеса и проверенные источники NHS, ACMG, TIDE/Van Karnebeek, RCH, MPSE.
- `lib/model.ts`: максимум выбранных весов внутри каждой категории, сумма максимум 100. Диапазоны 0–24 / 25–49 / 50–100 демонстрационные.
- Пустой/неизвестный ввод не обозначает отсутствие признаков. До известного ответа показывается «Нет данных». Состояния «не заполнено», «нет данных», «не выявлены» сохраняются отдельно.
- Веса и пороги отсутствовали в PRD. Это не валидированный медицинский алгоритм и не вероятность диагноза. Источники подтверждают контекст признаков, но не веса. MPSE/TIDE не выдаются за используемый алгоритм.
- Клинический календарь использует `Asia/Almaty` одинаково в браузере и сервере; возраст считается на дату приёма. Часовой пояс задаётся в `lib/patient.ts`.
- История в серверной версии хранится в D1, временный несохранённый ввод — в `sessionStorage`. Ошибка сохранения не очищает форму. Восстановление сохраняет структурно корректный черновик даже при незавершённой валидации отдельных полей.
- Создание новой оценки всегда использует новый ID. Изменения существующего случая обновляют его сохранённую запись.
- `.openai/hosting.json` связывает серверную версию с закрытым Sites-пространством. Локальная тестовая база `.wrangler/` не публикуется. Аккаунты клиники/разделение доступа между врачами не реализованы. Публичная Pages-версия работает без этой базы.

## Границы готовности

Это функциональный прототип интерфейса. Для клинической эксплуатации необходимы утверждённые веса и пороги, валидация, регламент обработки медицинских данных и аудит доступа. Английская локализация, МИС/EHR, аккаунты клиники и автономная работа без соединения не входят в эту сборку. PDF создаётся штатным диалогом печати, направление не отправляется внешнему получателю.

Два WebMCP-инструмента используют состояние экрана: чтение текущей оценки и заполнение несохранённых признаков. Они не сохраняют запись и не отправляют направление.
